# تجهيز إصدار جديد

نفّذ الخطوات بالترتيب. إذا فشلت خطوة، توقّف وأبلغ مصطفى، ولا تكمل.

## 1. رفع رقم الإصدار
- اقرأ `version:` في `pubspec.yaml` (الصيغة `X.Y.Z+BUILD`).
- اسأل عن نوع الإصدار إن لم يُذكر: إصلاح (Z) أو ميزة (Y) أو كبير (X).
- ارفع الجزء المطلوب وصفّر ما بعده، **وارفع رقم البناء BUILD بواحد دائماً**
  (Google Play يرفض رقم بناء مكرّر أو أصغر).

## 2. التحقق
```
flutter analyze
flutter test
```
كلاهما يجب أن ينجح. ممنوع تعطيل اختبار أو تخفيفه لتمرير الإصدار.

## 3. المراجعة
- حدّد آخر إصدار: `git describe --tags --abbrev=0` (إن لم يوجد وسم، فمن أول commit).
- شغّل الوكيل `code-reviewer` على `git diff <آخر-إصدار>..HEAD` مع `git log` لنفس المدى.
- إذا كان في تقريره بند تحت "أصلحه الآن"، توقّف واعرضه على مصطفى.

## 4. ملاحظات الإصدار
اكتبها في `docs/releases/<الإصدار>.md` للمستخدمين، لا للمطوّرين:
- قسم **العربية** ثم قسم **English**.
- 3 إلى 6 نقاط مختصرة لكل قسم: الجديد، والتحسينات، والإصلاحات.
- لغة بسيطة بدون أسماء ملفات أو مصطلحات برمجية.
- حدّث `docs/features.md` إن تغيّرت حالة أي ميزة.

## 5. Commit
- commit واحد: `release: vX.Y.Z+BUILD` يضم `pubspec.yaml` وملاحظات الإصدار و`docs/features.md`.
- لا تنشئ وسماً (tag) ولا تعمل push إلا إذا طلب مصطفى ذلك.
- اعرض في النهاية: رقم الإصدار، ونتيجة analyze/test، وملخص تقرير المراجعة، ونص الملاحظات.
